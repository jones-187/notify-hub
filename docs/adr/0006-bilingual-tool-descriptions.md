# 工具说明用中英双语，英文在前

MCP 工具的说明文字用**中英双语**：英文一句在前，中文原文在后。字段说明同理，短的加英文，
长的保留中文（里面已有 `scheduled_at`、`Asia/Shanghai`、`RFC3339` 这些 ASCII 词可以搜到）。

理由：客户端的工具检索索引**不切分中文**。实测 pi 的 `searchTools`：用「通知」「提醒」「排期」
查都是 0 命中，而用 `last_error`（只出现在说明正文里的英文词）却能命中——说明索引里有说明
正文，但分词器只认 ASCII。只写中文时，agent 拿中文概念检索这个服务是**完全搜不到**的。
英文那句既是给人的说明书，也是能被检索的键。

已经有客户端踩过：pi 的 agent 不知道有这条通道，另造了一套定时机制。

## Considered Options

- **只写中文**：检索全空，只能靠客户端把服务名和说明塞进系统提示。已踩过。
- **只写英文**：机主读的是中文，说明会变难读。
- **堆关键词**（例如 `keywords: notify, remind, reminder`）：对人难读，是痕迹明显的 stuffing。否决。

## Consequences

- 加工具、改说明时，**英文那句不要删**，它不是重复。`tests/test_mcp_ingress.py` 里有测试盯着。
- 客户端若按说明做检索，**中文查询仍然搜不到**——这是客户端分词器的限制，服务端只能提供
  能被 ASCII 匹配的词。
- 说明变长：以 `direct` 方式暴露工具的客户端，每轮上下文会多花几十个 token。
